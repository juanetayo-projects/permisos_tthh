## PRIMERO ##

NO escribas código inmediatamente.

Primero debes actuar como un Software Architect Senior.

Analiza completamente este proyecto.

Antes de crear un solo archivo debes entregar:

1. Arquitectura completa.
2. Modelo de datos.
3. Módulos.
4. Flujo de navegación.
5. Casos de uso.
6. Roles.
7. Wireframes.
8. Riesgos.
9. Mejoras.
10. Preguntas pendientes.

Si encuentras inconsistencias en este documento debes proponer alternativas.

Cuando todo esté aprobado comenzarás el desarrollo.

## OBJETIVO ##

Construir una aplicación empresarial para la gestión completa de permisos y ausentismos del personal de la Clínica de Alta Complejidad Santa Bárbara.
El sistema reemplazará completamente el proceso manual en papel.
Debe cumplir estándares de calidad ISO 9001.
Debe ser altamente mantenible.
Debe poder crecer en módulos.
Debe ser escalable.
Debe seguir principios SOLID.
Debe seguir Clean Architecture.
Debe utilizar Domain Driven Design donde aplique.
Debe estar preparado para auditorías.

## FILOSOFIA ##

Todas las decisiones deben priorizar:

• simplicidad
• mantenibilidad
• escalabilidad
• experiencia del usuario
• velocidad
• accesibilidad
• seguridad
Nunca generar código duplicado.
Siempre reutilizar componentes.
Todo debe ser responsive.
Todo debe estar tipado.
Todo debe documentarse.
Todo debe incluir pruebas cuando sea posible.
